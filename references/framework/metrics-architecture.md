# TNFD Metrics Architecture

> Purpose: Use when preparing metrics, targets, dashboards, or assurance-readiness checks.

## Source Status

- Source type: Official TNFD metrics architecture summary.
- Last reviewed locally: 2026-04-29.

## Metric Types

| Type | Role | Disclosure use |
|---|---|---|
| Core global disclosure metrics | Cross-sector metrics expected on a comply-or-explain basis | Prepare and assurance-readiness |
| Core sector disclosure metrics | Sector-specific metrics from TNFD sector guidance | Prepare for relevant sectors |
| Additional disclosure metrics | Optional or context-specific metrics | Support richer disclosure |
| Assessment metrics | Internal LEAP assessment metrics | Use for analysis; disclose only if material and robust |

## Comply Or Explain

For each relevant core global metric:

1. Report the metric, or
2. Explain why it is not reported, including data limits, methodology constraints, timing, or relevance.

## Minimum Metric Table

| Metric | Category | Reported? | Value | Boundary | Source | Method | Limitation | Comply/explain |

## Targets

Targets should include:

- Baseline value and year
- Target value and year
- Scope and boundary
- Scientific or policy basis where applicable
- Owner and governance route
- Progress metric
- Limitation or uncertainty

## Internal Heuristics

Internal heat maps, ENCORE screens, BRF outputs, and custom risk scores may support prioritisation. Do not present them as official TNFD metrics unless they map to a TNFD disclosure metric and the method is explained.
